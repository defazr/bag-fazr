## F-1. `/seoul/gangbuk` 오염 데이터 — P0

```
data/seoul/gangbuk.json  district="강북구"  totalCount=1779
  대구광역시 북구  948
  광주광역시 북구  722
  울산광역시 북구  108
  부산광역시 북구    1
  서울 주소          0 / 1779
```

라이브 확인 시점 본문에 `대구광역시` 1,827회 / `광주광역시` 1,315회 노출.

**근본 원인.** v1 `collect.py`(`3751c31`)의 부분 매칭 fallback.

```python
# v1 — 지역 차원 없이 구 이름만으로 매칭
grouped: dict[str, list[dict]] = {}      # slug -> stores
district_name = extract_district(addr)   # region 인자 없음
slug = name_to_slug.get(district_name)
if not slug:
    for name, s in name_to_slug.items():
        if district_name in name or name in district_name:
            slug = s; break
```

실제 `lib/regions.ts`로 재현한 결과:

```

남구 → 강남구    동구 → 강동구    서구 → 강서구
중구 → 정확매칭 성공 (junggu)   ← 중구가 오염되지 않은 이유
```

v2(`ae1b916`)가 `DISTRICT_SLUG_MAP.get(region_slug)`로 지역 스코프를 확정해 분류 자체는 고쳤으나, **저장 로직에 stale 파일 삭제가 없어** 3/27 09:27 교정 실행이 `index.json`만 갱신하고 고아 `gangbuk.json`은 그대로 남았습니다. 그 결과 오염이 5개월간 라이브 유지.

**조치.**

1. `data/seoul/gangbuk.json` 삭제 (12,463줄)
2. `scripts/collect.py` — 부분 매칭 fallback 제거. 정확 매칭 실패 시 `_unmatched.json` + `log.warning`으로 드러냄
3. `scripts/collect.py` — `count == 0`이면 기존 `{slug}.json` 삭제
4. `scripts/collect.py` — 저장 직전 지역 일치 검증. 주소의 시/도가 저장 대상 지역과 다른 매장은 기록하지 않고 `log.error`

## F-2. og:image 등 OG 필드 소실 — P1

**증상.** 홈을 제외한 **249개 페이지 전부** `og:image` 없음.

```
/                     og:image=1  twitter:image=1
/seoul                og:image=0  twitter:image=1
/seoul/gangnam        og:image=0  twitter:image=1
/article/where-to-buy og:image=0  twitter:image=1
```

**원인.** Next.js `metadata`는 `openGraph` 객체를 **얕게 덮어씁니다.** 하위 페이지가 `{ title, description }`만 선언하면 root layout의 `images / url / siteName / locale / type`이 통째로 소실됩니다. `twitter` 객체는 오버라이드되지 않아 살아남았습니다.

영향: 카카오톡·네이버 카페/블로그 공유 시 전 구군 페이지가 썸네일 없는 텍스트 카드로 노출.

**조치.** `lib/seo.ts`에 `buildOpenGraph(title, description, path)` 단일 생성기를 추가하고, root layout을 포함한 **모든 선언부가 이 함수를 거치도록** 통일. 파일별 값 복사가 없으므로 드리프트 불가능.

적용: `app/layout.tsx`, `app/[region]/page.tsx`, `app/[region]/[district]/page.tsx`, article 3개.
`app/page.tsx`는 `openGraph` 미선언으로 layout을 온전히 상속하므로 미변경.

복구 결과 (`/seoul/gangnam`):

```
og:title / og:description / og:url / og:site_name /
og:locale / og:image / og:image:width / og:image:height / og:type
```

### P3-2. AdSense 마크업이 서버 HTML에 0개

라이브 홈 HTML 실측: `<ins class="adsbygoogle">` **0개**, pagead2 `<script>` 로더 **0개**. `adsbygoogle` 문자열은 next/script가 넣은 `<link rel="preload">`와 RSC 페이로드 2곳뿐. 반면 GA 로더는 실제 `<script>` 태그로 존재합니다.

`AdSlot.tsx:43`의 `if (!mounted) return null`과 `layout.tsx:63`의 `<Script strategy="afterInteractive">` 조합 때문입니다. 실사용자는 JS 실행 후 광고를 보므로 수익 즉시 중단은 아니나, **문서 룰 #3 "AdSense: 일반 `<script>` 태그 (next/script 금지)"와 현재 코드가 반대**입니다(`85d71ff`가 뒤집음). 문서와 코드 중 하나는 틀린 상태이므로 어느 쪽을 정본으로 할지 결정이 필요합니다.

부수: `StickyBottomAd.tsx:7`의 `max-h-[100px] overflow-hidden`이 반응형 유닛을 자르고, `format="fluid"`인데 `data-ad-layout(-key)`가 없습니다. `ScrollToTop`(`fixed bottom-6 right-6 z-50`)이 하단 광고를 덮습니다.

### P3-3. sitemap `lastmod`가 전 URL 빌드 시각

`sitemap.ts:8-31` 5개 호출부 전부 `lastModified: new Date()`. 242개 URL이 3ms 이내 동일 값이며, 실제 데이터는 `updatedAt: 2026-03-27` 고정입니다. 배포마다 전 페이지가 변경됐다고 신고하는 셈이라, 색인 회복 대기 중인 상태에서 불리하게 작용할 수 있습니다. 구군별 `updatedAt`이 이미 있으므로 그 값을 쓰면 됩니다.

### P3-4. `BreadcrumbList` 미발행

`components/seo/Breadcrumb.tsx`는 `components/seo/`에 있고 246개 페이지에서 `<nav aria-label="breadcrumb">`를 정상 렌더하지만 **JSON-LD를 전혀 발행하지 않습니다.** 사이트 전체 구조화 데이터는 `FAQPage` 하나뿐입니다. `WebSite`/`Organization`(홈), `Article`(article 3개, 가시 날짜선은 있으나 `datePublished`/`dateModified` 없음)도 부재.

### P3-5. 검색어 공백 처리 누락
